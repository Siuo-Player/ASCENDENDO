# ASCENDENDO — Roadmap operacional — 2026-09-06

Novo snapshot operacional datado; os anteriores permanecem históricos.

## Baseline

`main` observado: `4cde0acc594c5f26f82d001cba5203906a3b53e3`.

## Sequência operacional

```text
exact asset binaries + provenance
→ technical integration
→ CI
→ deterministic capture
→ human visual validation
→ curated props/environment
→ audio design/implementation
→ release hardening
```

## 9.8 — assets

### Bloqueadores

- [ ] obter os ficheiros binários exatos dos candidatos aprovados;
- [ ] verificar tamanho, formato, provenance/licença e compatibilidade;
- [ ] integrar apenas os ficheiros concretamente presentes;
- [ ] executar testes e deterministic capture após integração;
- [ ] não inferir existência de ficheiro a partir de preview, nome ou registry.

## 9A — validação visual

- [ ] validar editor e jogo em múltiplos aspect ratios;
- [ ] verificar legibilidade, hierarquia, contraste, profundidade e affordances;
- [ ] manter revisão humana independente dos resultados estruturais/CI.

`deterministic capture` demonstra estabilidade da captura; não demonstra qualidade visual.

## 9.9 — props/environment

Só iniciar depois de 9.8 possuir assets concretos integrados e uma base visual minimamente validada.

## 9.5 — physical/campaign validator

Permanece separado do validador semântico do editor. Só criar orquestração adicional quando surgir necessidade concreta de produto. A diferença entre as camadas deve continuar visível no estado/documentação.

## 9C — audio

Tratar como workstream independente:

```text
gameplay event
→ semantic audio event
→ sound identity
→ priority/concurrency/mix
→ spatialisation
→ accessibility
```

Audio não pode tornar-se segunda fonte de regras de gameplay.

## Gates permanentes

```text
metadado ≠ ficheiro
CC0 ≠ aprovação
CI ≠ qualidade visual
capture ≠ playtest
semântica ≠ validação física completa
```
